# QA Sweep — July 2026

Three independent review passes (core math/parsers, app layer/concurrency,
network/data/launch readiness) with live endpoint probes. All findings below
were verified with a concrete trigger before fixing. The WMM port was
independently re-verified against the NOAA reference implementation
(agreement < 5×10⁻⁷ °) and the coefficient table diffed 90/90 against the
official WMM-2025 .COF.

## Fixed (this commit)

**Blockers**
- Offline chart downloads aborted on the first out-of-coverage tile (FAA
  tile services 404 outside a chart's footprint). Prefetch now skips and
  counts unavailable tiles; only cancellation stops a download.
- The scheduled data-refresh loop would have produced a *date-less* plate
  index next cycle (main still carried the old generator), permanently
  disarming the staleness system via the isNewer cycle-string fallback.
  Fixed twofold: isNewer now never lets an undated index beat a dated one,
  and main is fast-forwarded to this line of work so the workflow runs the
  dated generator. Cron moved from Mondays to Thursdays 13:00 UTC (cycles
  flip Thursdays 0901Z); note: the refresh PR still needs a human merge.

**Major**
- Crash: clearing the route while the airport DB was still loading could
  trap on a force-unwrap in the winds-aloft refresh (guard re-checked after
  suspension now).
- TFR false all-clear: if the TFR list loaded but every geometry fetch
  failed, the UI showed a fresh "0 active TFRs". Now keeps previous data
  and surfaces an error.
- Dismissing a screen mid-fetch recorded task cancellation as a network
  failure ("Offline" banner / TFR error with full connectivity). Cancellation
  is now silent; only genuine connectivity errors set offline state.
- Non-200 TAF responses (CDN error pages) could be stored and persisted as
  a station's TAF. Status + content sanity checks added; same hardening for
  METAR/windtemp status codes and ArcGIS 200-with-error-body responses.
- Offline charts and plates lived in Caches/, which iOS purges under
  storage pressure. Moved to Application Support (backup-excluded), and
  chart tiles are now cycle-keyed with old cycles pruned, so a new chart
  edition is never shadowed by stale rasters.
- Airport pages for the ~13k non-METAR fields showed a perpetual
  "Fetching METAR…" spinner. Terminal empty-states added (detail + briefing).
- A stale undated plate-index cache could shadow a newer dated bundle and
  silently disable expiry warnings (isNewer ordering fixed).
- Transient PIREP 5xx wiped displayed pins (now keeps the previous set);
  offline-download cancel/restart race could clobber the active download's
  UI handle (token-guarded now).

**Core math**
- Antimeridian bounding boxes produced zero tiles (Aleutians offline
  downloads impossible) — tile enumeration now wraps modulo 2^z; the
  map's box-center longitude also wraps correctly.
- VOR frequencies on 50-kHz channels displayed wrong (108.05 → "108.0");
  now two decimals with trailing-zero trim.
- Loading exactly at max gross on the envelope edge was reported outside
  the CG envelope while the weight check called it legal; boundary points
  now count as inside, consistently.

**Minor**
- Plate PDFs validated (%PDF magic) and written atomically; remote index
  fetch uses a 20 s-timeout session and decodes off the main actor;
  marker-image cache moved to thread-safe NSCache (Swift-6-proof);
  App Store listing: removed the data-self-update overclaim and the NOTAM
  keyword, fixed policy URLs, MARKETING_VERSION 1.0.0,
  ITSAppUsesNonExemptEncryption=NO.
